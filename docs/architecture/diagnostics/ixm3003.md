# IXM3003: broad exception catch must rethrow

## Rationale

A broad catch that returns, falls through, replaces the exception, or converts it to a result can hide cancellation, programming faults, corrupt state, and unexpected technical failures.

## Required control flow

Every reachable path in an untyped catch or `catch (Exception)` must end with bare `throw;`. Logging and cleanup before that rethrow are valid. Specific catches are not automatically valid translations: they need a documented, caller-actionable expected outcome and a coded error. Cancellation always propagates.

## Review boundary

The analyzer establishes broad-catch structure. Reviewers decide whether a specific exception represents an expected outcome and whether state changes remain failure-atomic.
