# IXM1001: public data object requires complete XML documentation

## Trigger

The rule applies to externally visible records, `Contracts` data types, and types whose names use an approved data suffix. It reports both an incompletely documented data-object declaration and its directly declared, externally visible non-positional members. Generated, implicit, inherited, and non-user-authored symbols are excluded.

## Rationale

Public data objects cross library boundaries and are often serialized, cached, compared, or retained by consumers. Their meaning must be visible without reading implementation source. A complete summary and documented public data surface make nullability, units, ownership, and defaults reviewable.

## Noncompliant example

```csharp
/// <summary>Describes a page of library query results.</summary>
public sealed record PageResult<T>(IReadOnlyList<T> Items, int Offset)
{
    public int TotalCount { get; init; }
}
```

`Items` and `Offset` are positional-record parameters and need `<param>` entries on the record declaration. `TotalCount` is a directly declared externally visible member and needs its own complete documentation.

## Compliant example

```csharp
/// <summary>Describes a page of library query results.</summary>
/// <typeparam name="T">The item type.</typeparam>
/// <param name="Items">The items in their documented order.</param>
/// <param name="Offset">The zero-based offset represented by this page.</param>
public sealed record PageResult<T>(
    IReadOnlyList<T> Items,
    int Offset)
{
    /// <summary>Gets the total number of matching items.</summary>
    /// <value>The total number of matching items.</value>
    public int TotalCount { get; init; }
}
```

## Remediation

Add a non-empty `<summary>` to the type and every in-scope member. Add each applicable non-empty `<param>`, `<typeparam>`, `<returns>`, and `<value>` element. Positional-record parameters are documented on the record declaration; ordinary externally visible members are documented on their declarations.

## Exceptions

Compiler-generated, implicit, inherited, and non-user-authored symbols are outside the rule. Internal implementation-only data is outside this public-library rule. Do not use an exception to hide an unclear public data contract; reduce the surface or document it.

## Suppression

The package default is warning and this repository configures it as error. A narrow suppression needs a documented compatibility reason, an owner, and a review date. `CS1591` is disabled; it is not a substitute for this focused policy.
