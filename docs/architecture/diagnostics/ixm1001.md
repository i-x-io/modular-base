# IXM1001: public data object requires complete XML documentation

## Rationale

Public data objects cross library boundaries and are often serialized, cached, compared, or retained by consumers. Their meaning must be visible without reading implementation source. A complete summary and documented public data surface make nullability, units, ownership, and defaults reviewable.

## Example

```csharp
/// <summary>Describes a page of library query results.</summary>
public sealed record PageResult<T>(
    /// <summary>The items in their documented order.</summary>
    IReadOnlyList<T> Items,
    /// <summary>The zero-based offset represented by this page.</summary>
    int Offset);
```

## Exceptions

Compiler-generated, implicit, inherited, and non-user-authored symbols are outside the rule. Internal implementation-only data is outside this public-library rule. Do not use an exception to hide an unclear public data contract; reduce the surface or document it.

## Suppression

The package default is warning and this repository configures it as error. A narrow suppression needs a documented compatibility reason, an owner, and a review date. `CS1591` is disabled; it is not a substitute for this focused policy.
