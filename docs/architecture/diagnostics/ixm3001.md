# IXM3001: service operation must return FluentResults

## Rationale

Externally visible service operations expose expected success and failure to callers. `Result` or `Result<T>`, directly or in `Task` or `ValueTask`, keeps that outcome explicit and transport-neutral.

## Required shape

The service contract must return `FluentResults.Result`, `FluentResults.Result<T>`, `Task<FluentResults.Result>`, `Task<FluentResults.Result<T>>`, `ValueTask<FluentResults.Result>`, or `ValueTask<FluentResults.Result<T>>`. The interface declaration owns the report; an implementation is not reported again unless it exposes an additional public service operation.

## Review boundary

The analyzer checks return shapes, not business semantics. Review whether failures are expected and whether changing an existing raw public return type is a breaking API migration.
