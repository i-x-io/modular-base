# IXM1002: public interface requires complete XML documentation

## Rationale

An interface is a consumer contract, not merely a shape inferred from names. Its summary defines the capability, lifecycle, and caller expectations that implementations must preserve.

## Example

```csharp
/// <summary>Resolves a named library capability without selecting its implementation.</summary>
public interface ICapabilityResolver
{
    // Members have their own IXM1003 contract.
}
```

## Exceptions

Only user-authored public interfaces are in scope. Generated interfaces and internal implementation seams are excluded. A terse name is not an exception when a consumer could misunderstand ownership, lifetime, or failure behavior.

## Suppression

The package emits a warning; repository policy promotes it to error. Suppress only adjacent to a deliberately exceptional declaration, with an explanation and review date. Do not use a file-wide or project-wide suppression.
