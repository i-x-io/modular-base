# IXM1005: service interface member requires complete XML documentation

## Rationale

Service interface members carry the operational contract: inputs, outputs, generic constraints, cancellation, ownership, and observable effects. Complete XML documentation makes that contract available to consumers at the call site.

## Example

```csharp
/// <summary>Executes one validated library operation.</summary>
/// <param name="request">The immutable operation request.</param>
/// <param name="cancellationToken">Cancels work before completion.</param>
/// <returns>The operation outcome.</returns>
public ValueTask<OperationResult> ExecuteAsync(
    OperationRequest request,
    CancellationToken cancellationToken);
```

## Exceptions

The rule applies to members of service interfaces, including inherited service interfaces; generated, implicit, and non-user-authored members are excluded. The rule does not make all implementation exceptions public contract; document a caller-actionable exception only when the library intentionally promises it.

## Suppression

Repository severity is error. Prefer completing the documentation. Any local suppression must state why the API cannot be documented now, name an owner, and specify a review date.
