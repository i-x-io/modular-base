# IXM1005: service member requires complete XML documentation

## Trigger

The rule applies to externally visible members of service interfaces and to externally visible members directly declared by a non-interface service type. External visibility includes `public`, `protected`, and `protected internal` members. It does not report inherited implementation members again, but it does analyze a service interface's own externally visible members.

## Rationale

Service interface and service-class members carry the operational contract: inputs, outputs, generic constraints, cancellation, ownership, and observable effects. Complete XML documentation makes that contract available to consumers at the call site.

## Noncompliant example

```csharp
public sealed class OperationService
{
    public ValueTask<Result<OperationResult>> ExecuteAsync(
        OperationRequest request,
        CancellationToken cancellationToken) => throw new NotImplementedException();
}
```

`ExecuteAsync` is externally visible and directly declared by a non-interface service type, so it is in scope.

## Compliant example

```csharp
/// <summary>Executes one validated library operation.</summary>
/// <param name="request">The immutable operation request.</param>
/// <param name="cancellationToken">Cancels work before completion.</param>
/// <returns>The operation outcome.</returns>
public ValueTask<Result<OperationResult>> ExecuteAsync(
    OperationRequest request,
    CancellationToken cancellationToken);
```

## Remediation

For every in-scope service-interface member or externally visible member directly declared by a non-interface service type, add a non-empty `<summary>` plus each applicable `<typeparam>`, `<param>`, `<returns>`, and `<value>` element.

## Exceptions

The rule applies to members of service interfaces, including inherited service interfaces, and externally visible members directly declared by non-interface service types; generated, implicit, and non-user-authored members are excluded. External visibility includes `public`, `protected`, and `protected internal` members. The rule does not make all implementation exceptions public contract; document a caller-actionable exception only when the library intentionally promises it.

## Suppression

Repository severity is error. Prefer completing the documentation. Any local suppression must state why the API cannot be documented now, name an owner, and specify a review date.
