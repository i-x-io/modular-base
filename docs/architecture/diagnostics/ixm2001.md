# IXM2001: data objects should be records

## Rationale

Records can make value-oriented data contracts concise and communicate value equality. This diagnostic is a nonblocking prompt for review; it does not establish that a class is immutable or semantically suitable for conversion.

## Example

```csharp
/// <summary>Identifies a library operation.</summary>
public sealed record OperationId(string Value);
```

## Exceptions

The analyzer selects only an externally visible data object that is a non-abstract, non-static, non-record class with no base type other than `object`. This is syntactic eligibility only: it does not infer immutability. Mutable lifecycle, identity, EF materialization, proxies, framework integration, interop, inheritance, reference equality, and compatibility are valid reviewed reasons to retain a class. Records change equality and generated members, so the suggestion never overrides a public API compatibility review.

## Suppression

`IXM2001` is info by default and a repository suggestion. Suppress it locally after review when a mutable lifecycle, identity, EF/proxy/framework/interop requirement, or another class contract is intentional; state the reason in a short explanation. It is nonblocking and must not be resolved by changing semantics merely to satisfy style.
