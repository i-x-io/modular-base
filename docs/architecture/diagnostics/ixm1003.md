# IXM1003: public interface member requires complete XML documentation

## Rationale

Interface members define what every consumer and implementation must agree on. A summary alone is incomplete where parameter, generic, or return semantics affect correct use.

## Example

```csharp
/// <summary>Resolves a capability by its stable key.</summary>
/// <param name="key">The key defined by the owning library contract.</param>
/// <returns>The resolved capability, or <see langword="null"/> when absent.</returns>
object? Resolve(string key);
```

## Exceptions

The rule excludes generated, inherited, implicit, and non-user-authored members. It does not demand an `<exception>` tag for every transitive exception. It does require every applicable `summary`, `param`, `typeparam`, and `returns` element to be non-empty.

## Suppression

Repository severity is error. Correct the contract first; an exceptional suppression must be local, justified, owned, and time-bounded.
