# IXM3002: Business failure must use a coded error

Direct FluentResults failure creation must use a concrete `FluentResults.Error` subtype with its own `public const string Code` in lowercase snake case. The code is the stable machine-readable failure contract; the message is explanatory text.

The rule rejects string-only failures, direct use of the base `Error` type, missing or invalid codes, and direct `Result.Try` calls. It validates statically visible failure construction only. A factory or collection that cannot be proven safe requires a narrow, justified suppression and review; it does not permit uncoded failures.

IXM3002 does not analyze projects whose `IXModularityProjectRole` is `Test`, `ArchitectureTest`, `Analyzer`, or `SourceGenerator` (case-insensitive).
